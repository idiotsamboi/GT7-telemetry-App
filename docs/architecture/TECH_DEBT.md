# Technical debt register

Format: **issue** · risk · recommended refactor · subsystem. Items marked *(new)* were registered by the
foundation pass; the rest predate it. The architecture tests carry allowlists that mirror this file
(`tests/test_architecture.py`): those lists may only shrink.

| # | Issue | Risk | Recommended refactor | Subsystem |
|---|---|---|---|---|
| 1 | `runtime.py` is still a god object (~45 KB): loops, ingestion, snapshot builder and the 200-line `execute()` intent handler live together. The pass extracted service wrappers, the bus subscribers and shared operations, but the loop bodies still live on `Runtime` | Every feature touches one file; hard to test loops in isolation | Move each loop body into its service's `run()` one at a time (start with `health_loop` → `diagnostics`), move `execute()` into an `EngineerService` (answers byte-identical, snapshot-tested over the 100 intents) and `snapshot()` into a `SnapshotBuilder` | runtime |
| 2 | `group/service.py` is ~53 KB | Review and merge friction | Split along natural seams only: roster/admission, race control state, workspaces/graphics, timing/publish | group |
| 3 | Older modules use a dense one-line style (`a;b;c`) | Diff noise, hidden bugs | Format only files you substantially change (ruff/black); no big-bang reformat | all |
| 4 | Two track systems: legacy `tracks.py`/`TrackMap` and v3 `track_service` + bundle | Duplicate state, two "locked" notions, `Runtime` feeds both | ADR 0009: v3 becomes the authority; legacy kept only as a fallback map store until user maps are migrated; then delete `TrackMap`, `LAYOUTS` consumers move to `track_catalogue` | tracks |
| 5 | Overlay subscribers re-authenticate against SQLite per tick and (before this pass) recomputed the snapshot per subscriber | CPU scales with OBS overlays | Snapshot cache per publication filter (done in this pass) + token cache with expiry check; measure with `scripts/group_load_test.py` | group/public |
| 6 | Test/dev SQLite data dirs (`data-frontend-dev/`, ~6 GB; `data-preview/`) live in the project folder | Disk use, accidental packaging | They are gitignored; move them out of the tree (`--data <path>`) and out of OneDrive | dev env |
| 7 | Project folder is inside OneDrive: SQLite WAL on a synced folder | WAL/SHM lock contention, corrupted sync of `.sqlite3-wal` | Keep the working tree outside OneDrive or exclude `data*/`; production installs use a local data dir | dev env |
| 8 | `release/` binaries are tracked in git | Repo bloat | Move release zips to GitHub Releases / artifact storage; keep only checksums | release |
| 9 | Stale README / release packages | Docs mismatch what ships | Regenerate README feature list from `docs/architecture/CONTRACTS.md` and `AI_CONTEXT.md` at release time | docs |
| 10 | Logging was essentially absent *(fixed in this pass)* | — | Structured logging exists (`core/logging_setup.py`); remaining `print`/bare `logging.exception` call sites in older modules should move to `log_event(...)` as they are touched | all |
| 11 | *(new)* Some module-level time-window deques have no `maxlen` (`group/history.py`, `tyre_heat.py`); pruned by time | Unbounded if the clock stalls | Give them a generous `maxlen` and drop from the allowlist in `test_architecture.py` | group/history, tyre_heat |
| 12 | *(new)* Engineer rules are declarative (`RuleSpec` in `engineer.py`, parity-tested against `tests/fixtures/legacy_engineer.py`), but `domain/alerts.py` still carries a second, descriptive `RuleDef`/`RULE_DEFS` that nothing populates | Two representations of one rule | Delete `RuleDef`/`RULE_DEFS` (or generate them from `RULE_SPECS`); delete the legacy oracle fixture after one release | engineer/domain |

| 14 | *(new)* Bus subscribers `sessions` (recorder) run in the original explicit order, not "critical first": `track_map` etc. run before `sessions` because session metadata reads the track state updated in the same frame | Reordering would change recorded metadata for the first frame of a session | Decouple by having `sessions` read a track snapshot taken at the end of the previous frame, then mark it critical | runtime/bus |
| 15 | *(new)* `storage` may import `telemetry` (units, canonical channels) and `domain/insights` and `storage/repositories` import `analytics`/`spatial_coaching` | Layering exceptions | Move `analytics.downsample` and the insight adapters' inputs behind small protocols in `domain/` | storage/domain |
| 16 | *(new)* Safe mode is triggered by the `.running` marker: a hard kill of the dev server (or `preview_stop`) makes the next start a safe start (no heartbeat until confirmed) | Surprise for developers | Turn off with `safe_mode_on_crash: false` in dev settings, or send the `safe_mode.leave` command (the frontend has no safe-mode UI yet) | runtime |
| 17 | *(new)* No `(session, lap_id)` index on `samples` | Lap-filtered reads use the session index | Add only if lap reads show up in profiling (it slows the write path) | storage |
| 18 | *(new)* Per-wheel reported channels (`tyre_temp_fl`, ...) are not registered; arrays are single channels | Frontend indexes arrays itself | Add scalar accessors if a panel needs them | telemetry |
| 19 | *(new)* Playwright e2e: 6 of 13 specs fail against the current tree (labels such as "Live Race" became "Pit Wall" in the in-progress UI redesign; also `Longitudinal acceleration`, Studio "Edit", the track-memory outline). They are UI-label drift from the redesign, not API regressions; not verified against a pre-pass baseline because the tree mixes uncommitted redesign work | Red e2e hides real regressions | The redesign owner updates `tests/e2e/*.spec.ts` with the new shell; keep `tests/e2e` green in CI afterwards | frontend/tests |
